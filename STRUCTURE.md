# STRUCTURE.md: repository layout

What every top-level entry is and why it exists. The rule: a line here
earns the entry's place. If you can't write the line, the entry is a
cleanup candidate.

## Directories

| Entry | Purpose |
|---|---|
| `tools/` | Everything Rail-source-but-not-compiler-or-stdlib: the compiler driver (`compile.rail`, `types.rail`, `ast.rail`), the runtime generator, the v5 assembler and linker (`v5/`), attestation (`attest/`), the verify scripts, the semantic oracle and GC stress driver (`fuzz/`), the test runner and smokes (`test/`), the REPL and LSP, the stdlib docs generator, the Quartz and channels bridges (`desk/`, `runtime/`), and `fleet/` until its daemon is repointed. |
| `runtime/arm64/` | The ARM64 runtime every native program links, as assembly (21 `.s` files). `tools/gen_runtime.rail` carries it into the compiler as the generated `tools/runtime_arm64.rail`. Root `runtime/` is otherwise gitignored build output. See its README. |
| `stdlib/` | Rail's standard library; the module count is a measured row of `docs/STATUS.md`. Everything `import`-able. |
| `examples/` | Hand-curated `.rail` programs that demonstrate language features, each with its expected output under `examples/expected/`; `tools/verify/examples_check.rail` runs them in CI. |
| `tests/` | Placeholder dir; the actual test corpus is inside `tools/compile.rail` as `run_test` calls. See `tests/README.md`. |
| `docs/` | Current-truth documentation: language ref, stdlib, ABI, release runbook, active design docs. Dated retros / closed investigations live in `docs/archive/`. |
| `grammar/` | EBNF grammar derived from `tools/compile.rail`'s parser, for grammar-constrained LLM decoding. One file. |
| `editors/` | Editor integrations (VS Code). |
| `tree-sitter-rail/` | Tree-sitter grammar for syntax highlighting. |
| `docs/archive/notes/` | Durable technical references (bootstrap-convergence audit, v5 feasibility, x86 conformance classification, the `v5_macho_ref/` Mach-O layout bundle). |
| `releases/` | One subdirectory per tagged release (51 entries) holding the Ed25519 attestation JSONs + `index.json`. The signed bytes (`rail_native` + `compile.rail`) are recoverable from each git tag, so HEAD keeps only the proof. Published to `ledatic.org/releases/`. |
| `builds/` | One subdirectory per attested intermediate build (13 entries): `result.json` + its attestation, no binary. The build-time analogue of `releases/`, for non-tagged commits. |
| `selfhost/` | Self-host fixed-point attestation artifacts: proof that a given `rail_native` 2-pass-compiles itself byte-identically. |
| `archive/` | **Gitignored.** Local-only retention for stale artifacts moved out of the public tree. |

## Conventions enforced here

- **Dated filenames belong in archives.** If a doc has `YYYY-MM-DD` in its name, it lives in `docs/archive/` (tracked) or `archive/` (gitignored), not at the canonical surface.
- **Single-file `tools/` subdirectories are intentional.** `tools/docs/` and `tools/independence/` each hold one tool that is one file. Not abandoned stubs: the tool *is* the dir's contents.
- **`archive/` (top-level) is gitignored.** Local-only retention. Files moved there leave git history.
- **`docs/archive/` is tracked.** Dated retros / handoffs / closed investigations stay browsable.
