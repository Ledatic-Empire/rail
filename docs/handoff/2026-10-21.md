Found by the first in-process link of user programs, all fixed in #160, each with a loud path where
there was a silent one (CHANGELOG `Unreleased / Changed / One link path` has the detail):

1. the assembler decoded `\r` in `.asciz` as the letter r (t211 cr_escape); the committed seed's own
   `"\r"` literal in `strip_trailing_ws_loop` had been `"r"` since v5.2.0 (33 bytes differed
   between gen1 and gen2 of the first bootstrap, one of them `72` to `0d`);
2. `ror` (register), `smulh` and `fneg` had no encoding and were written as `0xffffffff`
   (SIGILL at run time); now `asm: no encoding for ...` names the line and the link is refused;
3. `.comm _memo_<fn>,8192,3`, the auto-memo table, was not a symbol the linker knew, so its
   `adrp`/`add` pointed at page 0 (t2 fact returned 175, t91 tco, generate_ct, selfloop_arg_shapes);
   `lk_bake_pass_r` had counted the unresolved reference and `lk_link_file` dropped the count;
4. an undefined identifier (`_RAIL_UNDEFINED_IDENT_<name>`, which ld refused) would have bound to
   libSystem and died in dyld at launch; the linker refuses it by name (`link: refused, undefined
   identifier(s): y`, exit 1, no binary) and the assembler skips the `; ERROR` comment line;
5. `./rail_native tools/compile.rail` had failed at ld for months: `build`'s `grep -c 'b _llm'`
   matched its own string literal in the compiler's data section and asked for a `runtime/llm.o`
   that left the tree. The file driver now produces the seed byte for byte.
