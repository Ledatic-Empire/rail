# Architecture: layers, boundaries, where a change goes

Measured from the import graph on 2026-11-27. Each rule below names the gate that holds it.

## Layers and the direction of dependency

```
tools/compile.rail  tools/types.rail  tools/ast.rail     the compiler (one program)
        |
tools/v5   assembler (asm, arm64) and in-process linker (link_lib)
        |
stdlib/    the modules (count in docs/STATUS.md): bytes, sha256, macho, codesign, json, tls13, ...
```

Programs that sit beside the compiler and import down only: `tools/verify` (gates),
`tools/attest` (signing and the verifier), `tools/fuzz`, `tools/test`, `tools/independence`,
`tools/fleet` (deferred), and `examples/`.

| Rule | Gate |
|---|---|
| stdlib imports no file under `tools/` | `tools/verify/stdlib_alone.rail` |
| `tools/v5` imports only stdlib and itself | same |
| No top-level name defined in two stdlib modules | same |
| A stdlib module imports every module it uses, so it compiles alone | same |
| No import cycle among stdlib, `tools/v5` and the compiler files (the compiler does not terminate on one, so this runs before any module is compiled) | same |

## Public interface of each layer

- **Compiler:** the `rail_native` command (`run`, `test`, `self`, `x86`, `linux`, `get`, `pkg`) and
  the error format `file:line:col: error: message`. Internals are walked by `docs/COMPILER_TOUR.md`
  and pinned by `tools/verify/tour_check.rail`.
- **tools/v5:** `lk_link_file` in `link_lib.rail` (assemble, lay out, bind, sign). `asm.rail` and
  `arm64.rail` are its encoder; `tools/verify/neon_enc.rail` holds the encoder to Apple clang.
- **stdlib:** one module per file, public names listed in `docs/site/stdlib.md` (generated by
  `tools/docs/gen_stdlib_ref.rail`). A module's helper names carry a module prefix when it must stay
  self-contained (ADR-5, `docs/entropy/DECISIONS.md`).
- **Runtime:** `runtime/arm64/*.s`, embedded through `tools/gen_runtime.rail`; the variables it reads
  are listed in `docs/STATUS.md`, generated from `runtime/arm64/data.s`.

## Where a change goes

| Change | Edit | Then |
|---|---|---|
| New builtin | `builtin_call_names` and the `cg_bi` dispatch in `tools/compile.rail` | t287 fails when the two lists differ; rebuild the seed (below) |
| New stdlib module | `stdlib/<name>.rail`, importing what it uses | `stdlib_alone.rail`, regenerate `docs/site/stdlib.md`, the module count moves in `docs/STATUS.md` |
| Runtime routine | the `.s` file, then `tools/gen_runtime.rail` | bootstrap twice (`runtime/arm64/README.md`) |
| New suite test | a driver test in `tools/compile.rail` | every count of the suite (README, CLAUDE.md, `tour_check`) moves with it |
| Any change the compiler compiles into itself (its imports, `tools/v5`, `runtime/`) | the source | `RAIL_ARENA_MB=6000 ./rail_native self` twice, `cmp`, regenerate `docs/STATUS.md` in the same commit |
| A gate or check | `tools/verify/`, shared helpers in `tools/verify/lib.rail` | plant a defect and see it fail before trusting it |
